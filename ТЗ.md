# 📑 СИСТЕМНЫЙ ДИЗАЙН-ДОКУМЕНТ: ПЛАТФОРМА «Tap2Go»

## 1. Стек разработки (Tech Stack) & Обоснование

Для реализации высокопроизводительного, асинхронного и отказоустойчивого бэкенда выбираем следующий стек:

* **Язык программирования:** Python 3.11+ (использование преимуществ современной статической типизации через `typing`).
* **Главный фреймворк:** **FastAPI** — полностью асинхронный, имеет встроенную валидацию данных через PWA/Pydantic v2 и автоматическую генерацию документации OpenAPI (Swagger).
* **База данных:** **PostgreSQL** — надежная реляционная СУБД для хранения учетных записей, профилей, меню и логов.
* **ORM (Слой доступа к данным):** **SQLAlchemy 2.0 (Async)** в связке с асинхронным драйвером **asyncpg**. Никаких блокирующих синхронных запросов к БД.
* **Миграции базы данных:** **Alembic** — для контроля версий схемы данных.
* **Кэш и Rate Limiting:** **Redis** + библиотека `redis-py` (aioredis). Необходим для мгновенной проверки замков от флуда кнопками (TTL locks) и кэширования сессий.
* **Контейнеризация:** **Docker & Docker Compose** — для изоляции окружения разработки и быстрой развертывания одной командой.

## 2. Архитектура проекта и структура репозитория

Репозиторий строится по модульному принципу (Domain-Driven Service Layers), где каждый бизнес-домен изолирован внутри своей папки.

```text
tap2go/
│
├── alembic/                      # Сгенерированные миграции базы данных
├── data/                         # Локальные волюмы для персистентности Postgres и Redis
│
├── src/                          # Исходный код бэкенда
│   ├── __init__.py
│   ├── main.py                   # Точка входа: инициализация FastAPI, CORS-мидлварей, роутеров
│   ├── config.py                 # Валидация .env переменных через pydantic-settings (DB_URL, REDIS_URL)
│   ├── database.py               # Конфигурация движка SQLAlchemy (async_engine) и фабрики сессий (async_sessionmaker)
│   ├── exceptions.py             # Кастомные базовые ошибки API (HTTPException хэндлеры)
│   │
│   ├── auth/                     # Домен: Аутентификация B2B-клиентов (Владельцев)
│   │   ├── models.py             # SQLAlchemy модель таблицы `companies`

│       └── webhooks.py           # Эндпоинт приема платежных уведомлений от API банка (POST /runtime/webhook/payment)
```

## 3. Физическая архитектура базы данных (PostgreSQL Schema)

Каждая таблица проектируется с учетом строгого каскадного удаления (`ON DELETE CASCADE`) и индексации по полям, участвующим в частых выборках (`JOIN` и `WHERE`).

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 1. Корневые аккаунты компаний (B2B подписка)
CREATE TABLE companies (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,             -- Блокировка доступа, если подписка не оплачена
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Настройки кастомизации интерфейса под бренд (Связь 1:1 с коренной компанией)
CREATE TABLE company_profiles (
    company_id INT PRIMARY KEY REFERENCES companies(id) ON DELETE CASCADE,
    brand_name VARCHAR(100) NOT NULL,
    theme_color VARCHAR(7) DEFAULT '#FF5722',       -- HEX цвет (например, коралловый по умолчанию)
    button_text VARCHAR(50) DEFAULT 'Позвать официанта',
    is_menu_active BOOLEAN DEFAULT TRUE,             -- Флаг: показывать ли меню
    is_pay_active BOOLEAN DEFAULT FALSE,             -- Флаг: включена ли оплата СБП
    tg_staff_chat_id BIGINT DEFAULT NULL             -- ID Telegram-группы для резервного пуша
);

-- 3. Физические точки вызова (Столы, ПК, Кабинки)
CREATE TABLE locations (
    id SERIAL PRIMARY KEY,
    company_id INT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    name VARCHAR(50) NOT NULL,                       -- "Стол №1", "VIP-ПК 4"
    slug UUID DEFAULT uuid_generate_v4() UNIQUE,     -- Криптографический хэш для ссылки QR/NFC
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_locations_slug ON locations(slug);  -- Критически важный индекс для моментального Init-запроса

-- 4. Номенклатура цифрового меню / Каталог услуг
CREATE TABLE menu_items (
    id SERIAL PRIMARY KEY,
    company_id INT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    name VARCHAR(150) NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) NOT NULL,
    image_url VARCHAR(500),
    is_available BOOLEAN DEFAULT TRUE,               -- Флаг стоп-листа (есть ли в наличии)
    category VARCHAR(100) NOT NULL                   -- Категория: "Кальяны", "Кухня", "Напитки"
);
CREATE INDEX idx_menu_items_company ON menu_items(company_id);

-- 5. Транзакционный лог вызовов персонала (Для аналитики и "светофора")
CREATE TABLE staff_calls (
    id SERIAL PRIMARY KEY,
    company_id INT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    location_id INT NOT NULL REFERENCES locations(id) ON DELETE CASCADE,
    status VARCHAR(20) DEFAULT 'active',             -- Статусы: 'active' (горит красным), 'resolved' (обслужен)
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    resolved_at TIMESTAMP WITH TIME ZONE             -- Время закрытия вызова (для подсчета скорости работы)
);

```

## 4. Задачи для нейросети (Фронтенд-делегирование)

Поскольку твоя цель — хардкорный бэкенд, фронтенд полностью пишется искусственным интеллектом. Тебе нужно лишь поочередно скармливать нейросети следующие ТЗ.

### ТЗ №1: Клиентский интерфейс (`client.html`)

> **Промпт для ИИ:** Напиши код одного файла `client.html` (инлайновый CSS в `<style>` и чистый JavaScript без библиотек). Дизайн: Mobile-First, минималистичный премиальный PWA-вид (поддержка темной темы, системные шрифты Apple/Android, крупные элементы под тапы пальцем).
> **Логика работы JS:**
> 1. Скрипт парсит текущий URL и забирает `slug` (UUID из пути).
> 2. Делает асинхронный fetch-запрос `GET /api/v1/runtime/init/{slug}`.
> 3. Из JSON ответа берет `theme_color` и красит им главную кнопку, а в заголовок вставляет `brand_name` и `location_name`.
> 4. Если `is_menu_active` равен true, рендерит список товаров из массива `menu_items`, разбитый по категориям, с кнопками «+» в корзину.
> 5. При нажатии на главную кнопку вызова делает `POST /api/v1/runtime/call`. Если сервер отвечает кодом 429, кнопка блокируется, включается визуальный таймер обратного отсчета на 60 секунд с надписью «Персонал уже идет!».
> 6. Если в корзине есть товары и `is_pay_active` равен true, выводится кнопка «Оплатить через СБП», которая отправляет корзину на сервер и перенаправляет юзера по пришедшей ссылке из СБП-банка.
> 
> 

### ТЗ №2: Планшет Администратора (`admin.html`)

> **Промпт для ИИ:** Напиши SPA-страницу `admin.html` для планшета бармена. Верстка: CSS Grid, во весь экран, темный интерфейс (Dashboard).
> **Логика работы JS:**
> 1. При старте запрашивает `company_id` и открывает постоянный `new WebSocket("wss://домен/api/v1/runtime/ws/" + company_id)`.
> 2. Должен быть встроен механизм автоматического переподключения (reconnect loop), если связь оборвалась.
> 3. При получении JSON-события вызова (`status: 'active'`) на экране создается крупная карточка стола. Карточка должна циклично мигать мягким красным цветом, отображать время вызова (таймер «прошло минут:секунд») и проигрывать не раздражающий, но заметный звуковой сигнал (аудио-сигнал зашей прямо в код через base64).
> 4. На карточке есть кнопка «Обслужил». Клик по ней отправляет `PATCH` запрос на бэкенд для перевода вызова в статус `resolved`, и карточка плавно исчезает.
> 5. Добавь кнопку «Обновить принудительно», которая делает обычный `GET` запрос для ручной синхронизации статусов всех столов с БД, если вебсокет временно лагал.
> 
> 

### ТЗ №3: Панель управления Владельца (`dashboard.html`)

> **Промпт для ИИ:** Создай интерфейс личного кабинета владельца заведения `dashboard.html`. Верстка аккуратная, на базе чистого CSS (flexbox/tables).
> **Функционал:**
> 1. Блок «Кастомизация»: Input для ввода названия бренда, ColorPicker для выбора `theme_color`, Input для текста кнопки вызова. Три чекбокса-тумблера для флагов активации модулей (Меню, Оплата СБП, Контроль "Чаек"). Кнопка «Сохранить».
> 2. Блок «Столы»: Кнопка «Добавить точку». По клику отправляет запрос на бэкенд, получает новый UUID, генерирует и выводит на экран готовую ссылку для прошивки в NFC и QR-код (используй легковесную JS-библиотеку для QR из CDN).
> 3. Блок «Меню»: Простая CRUD-форма (Название, Описание, Цена, Категория, чекбокс «В наличии»).

## 5. Главный бэкенд-челлендж (Твоя дорожная карта)

Так как ты качаешь навыки бэкендера, вот 4 конкретные задачи, в которых тебе придется разобраться и написать сложную логику:

1. **Написание WebSocket Connection Manager:**
Тебе нужно создать Python-класс, который внутри оперативной памяти хранит словарь активных коннектов: `connections: dict[int, list[WebSocket]]`. Ключ — это `company_id`. Тебе нужно написать методы `connect()`, `disconnect()` и `send_personal_message()`. Главное — обернуть отправку в `try/except`, чтобы при любой ошибке сети мертвое соединение мгновенно удалялось из оперативной памяти, не вызывая утечек и падения сервера.
2. **Реализация TTL-замков в Redis:**
В роутере `POST /runtime/call` перед тем, как делать запись в БД, ты должен асинхронно постучаться в Redis:
```python
lock_key = f"lock:call:{company_id}:{location_id}"
is_locked = await redis_client.get(lock_key)
if is_locked:
    raise HTTPException(status_code=429, detail="Staff already notified")
await redis_client.set(lock_key, "active", ex=60) # замок на 60 секунд

```


3. **Обработка Идемпотентных Вебхуков от Банка:**
В файле `webhooks.py` банк будет стучаться к тебе при успешной оплате. Банки могут присылать один и тот же вебхук по 3 раза, если твой сервер не ответил им за 200 миллисекунд. Твой бэкенд должен уметь проверять: если статус заказа в БД *уже* изменен на «оплачено», мы просто игнорируем дубликат запроса и сразу возвращаем банку `HTTP 200 OK`, чтобы не выполнять повторно тяжелую логику.
4. **Middleware для Multi-Tenancy изоляции:**
Напиши кастомную зависимость FastAPI (`Depends`), которая при каждом запросе к защищенным эндпоинтам проверяет JWT-токен пользователя, достает оттуда его `company_id` и проверяет флаг `is_active` в таблице `companies`. Если флаг `False` (подписка закончилась) — API автоматически прекращает обслуживание запроса и выдает ошибку, полностью изолируя данные одной компании от другой.
