# 📑 СИСТЕМНЫЙ ДИЗАЙН-ДОКУМЕНТ: ПЛАТФОРМА «Tap2Go»

## 1. Стек разработки (Tech Stack) & Обоснование

Для реализации высокопроизводительного, асинхронного и отказоустойчивого бэкенда выбираем следующий стек:

* **Язык программирования:** Python 3.11+
* **Главный фреймворк:** **FastAPI** — асинхронность, валидация через Pydantic v2, автогенерация OpenAPI (Swagger).
* **База данных:** **PostgreSQL** — надежное реляционное хранилище для учетных записей, профилей, меню и логов.
* **ORM:** **SQLAlchemy 2.0 (Async)** + асинхронный драйвер **asyncpg**.
* **Миграции:** **Alembic** — контроль версий схемы данных.
* **Кэш, Real-Time и Сессии:** **Redis** + библиотека `redis-py` (aioredis). Проверка замков от флуда (TTL locks) и отслеживание активности столов для ИИ.
* **Фоновые задачи и ИИ-движок:** **APScheduler** (или **Celery**) + **Ollama API** (локальный запуск легковесной модели `Llama 3` или `Gemma 2` прямо на сервере разработки).
* **Контейнеризация:** **Docker & Docker Compose** — для изоляции окружения (app, postgres, redis, ollama).

## 3. Архитектура и схема базы данных (Database Schema)

Вместо плоских SQL-скриптов структура базы данных представляет собой строгую реляционную схему со связями «один-ко-многим» ($1:N$) и «один-к-одному» ($1:1$), защищенную каскадным удалением объектов.

### 🗺 Реляционные сущности данных (ER)

1. **`COMPANIES` (Корневой B2B-аккаунт)**
* `id` (Primary Key, Serial) — Уникальный идентификатор компании.
* `email` (VARCHAR, Unique, Indexed) — Логин владельца заведения.
* `password_hash` (VARCHAR) — Хэшированный пароль.
* `is_active` (BOOLEAN, Default: True) — Флаг активности b2b-подписки.
* `created_at` (TIMESTAMP) — Дата создания.
* *Связи:* $1:1$ с `company_profiles`, $1:N$ с `locations`, `menu_items`, `staff_calls`.


2. **`COMPANY_PROFILES` (Кастомизация UI и настройки ИИ)**
* `company_id` (Primary Key, Foreign Key -> `companies.id` ON DELETE CASCADE).
* `brand_name` (VARCHAR) — Название бренда заведения ("CyberZone", "Мята Lounge").
* `theme_color` (VARCHAR, Default: '#FF5722') — HEX-код цвета интерфейса для PWA.
* `button_text` (VARCHAR, Default: 'Позвать персонал') — Текст на главной кнопке.
* `is_menu_active` (BOOLEAN) — Флаг доступности цифрового меню.
* `is_pay_active` (BOOLEAN) — Флаг СБП-предоплаты.
* `ai_upsell_enabled` (BOOLEAN, Default: False) — Тумблер: включить ли ИИ-рекомендации при неактивности гостя.
* `ai_timeout_minutes` (INT, Default: 30) — Время ожидания перед генерацией пуша ИИ.


3. **`LOCATIONS` (Точки генерации QR/NFC кодов)**
* `id` (Primary Key, Serial).
* `company_id` (Foreign Key -> `companies.id` ON DELETE CASCADE).
* `name` (VARCHAR) — Человекочитаемое имя ("Стол №3", "VIP-ПК 5").
* `slug` (UUID, Unique, Indexed) — Криптографический токен для публичной ссылки.


4. **`MENU_ITEMS` (Номенклатура товаров/услуг)**
* `id` (Primary Key, Serial).
* `company_id` (Foreign Key -> `companies.id` ON DELETE CASCADE).
* `name` (VARCHAR) — Название позиции меню.
* `description` (TEXT) — Описание состава / характеристик (считывается ИИ для анализа).
* `price` (DECIMAL(10,2)) — Стоимость товара.
* `category` (VARCHAR, Indexed) — Категория ("Кальяны", "Кухня", "Напитки").
* `is_available` (BOOLEAN, Default: True) — Наличие (стоп-лист).


5. **`STAFF_CALLS` (Лог транзакций и вызовов)**
* `id` (Primary Key, Serial).
* `company_id` (Foreign Key -> `companies.id` ON DELETE CASCADE).
* `location_id` (Foreign Key -> `locations.id` ON DELETE CASCADE).
* `status` (VARCHAR, Default: 'active') — Статус вызова (`active` для светофора, `resolved` — выполнен).
* `created_at` (TIMESTAMP) — Время нажатия кнопки гостем.
* `resolved_at` (TIMESTAMP, Nullable) — Время закрытия заявки администратором.

## 4. Логика ИИ-модуля умных рекомендаций (`ai_agent/`)

Модуль предназначен для предотвращения простоев столов/игровых мест и мягкого увеличения среднего чека (Upselling) с помощью локальной нейросети.

### 🔄 Алгоритм контроля гостей (Асинхронный пайплайн)

1. При каждом действии гостя (сканирование QR, вызов персонала, добавление товара в корзину) бэкенд обновляет в Redis ключ `last_activity:{company_id}:{location_id}` с TTL (временем жизни).
2. Фоновый воркер (`ai_agent/worker.py`), используя планировщик (например, APScheduler), каждые 5 минут сканирует базу активных сессий в Redis.
3. Если время `now() - last_activity` превышает `ai_timeout_minutes` из настроек профиля компании, и у заведения включен `ai_upsell_enabled = True`, инициируется процесс генерации.
4. Сервис `ai_agent/service.py` собирает контекст:
* *Категория заведения и меню* (доступные к заказу `menu_items`).
* *История текущей сессии стола* (что они уже заказывали или какие кнопки нажимали).
* *Текущее время* (день/ночь).


5. Асинхронный клиент отправляет структурированный промпт в локальный контейнер **Ollama API** (`POST /api/generate`).
6. Нейросеть генерирует короткую, нативную фразу-предложение, которая через WebSocket выводится на экран смартфона гостя в виде всплывающего интерактивного баннера.

## 🚀 Главный бэкенд-челлендж (Твоя дорожная карта разработки по веткам)

Чтобы соблюдать идеальный Git-флоу, твой план разработки разбивается на 5 последовательных веток:

1. **`feature/infra-setup`** — Создание Docker-окружения, конфигурация PostgreSQL, Redis, Ollama, базовая инициализация FastAPI приложения и структуры каталогов.
2. **`feature/auth-tenant`** — Разработка моделей таблиц `companies` и `company_profiles`, хэширование паролей, генерация и валидация JWT-токенов, написание мидлвари для изоляции данных.
3. **`feature/menu-and-locations`** — Разработка CRUD для управления столами (генерация уникальных UUID) и цифрового меню заведений, настройка миграций Alembic.
4. **`feature/websocket-runtime`** — Создание `ws_manager.py`, программирование real-time ядра вызовов, интеграция системы анти-флуда (Rate Limiting) в Redis, обработка банковских вебхуков.
5. **`feature/ai-recommender`** — Реализация фонового воркера проверки активности, интеграция с Ollama API, создание промптов и отправка ИИ-предложений в WebSocket-канал клиента.
